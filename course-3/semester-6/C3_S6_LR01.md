# C3_S6_LR01. Установка сервера и первичная настройка

**Курс:** 3  
**Семестр:** 6  
**Блок:** Сервер баз данных и администрирование его компонентов  
**Связанная лекция:** [Установка и первичная настройка MySQL](https://olgakraven.github.io/2026-UIABD3-lecture/?topic=s06-02-install-initial-configuration&slide=1)

**Индивидуальный вариант:** 01–30; используйте строку своего номера из матрицы семестра.

## Ситуация

Новый учебный филиал получил чистую виртуальную машину. До загрузки базы администратор должен установить сервер и передать проверяемую карту конфигурации.

## Цель и навык

**Цель:** Развернуть изолированный учебный экземпляр MySQL и зафиксировать его основные параметры.

**Практический навык:** Устанавливать сервер, выбирать каталог данных, порт и режим службы, затем подтверждать готовность экземпляра.

## Исходные данные

- Учебная виртуальная машина Windows с правами администратора.
- Карточка варианта: порт, имя службы и каталог данных.
- Дистрибутив MySQL Community Server 8.4, предоставленный преподавателем.
- Форма журнала установки без паролей.

## Ограничения

- Работа выполняется только в учебной виртуальной машине.
- Пароль администратора не включается в отчёт и скриншоты.
- Порт и каталог выбираются по варианту; стандартные значения без обоснования не принимаются.

## Логический маршрут

1. Сверьте контрольную сумму и имя выданного дистрибутива.
2. Установите серверный компонент и задайте параметры варианта.
3. Настройте запуск экземпляра как службы.
4. Зафиксируйте фактические пути к исполняемым файлам, конфигурации и данным.
5. Запустите службу и выполните подключение клиентом.
6. Получите версию, порт и каталог данных запросом к серверу; сопоставьте их с вариантом.

## Что нужно помнить

- Служба ОС и учётная запись MySQL — разные сущности.
- Каталог установки не равен каталогу данных.
- Порт должен совпадать в конфигурации сервера и клиентском подключении.
- Команда SELECT VERSION() подтверждает ответ сервера, но не весь набор настроек.
- Пароли нельзя сохранять в истории команд и отчёте.
- Правильный результат подтверждается как состоянием службы, так и успешным SQL-запросом.

**Пример формы результата:** Ожидаемая форма фиксации: служба RUNNING; сервер отвечает; @@port и @@datadir совпадают с карточкой варианта.

**Типичная ошибка:** Установка подтверждена только скриншотом мастера, без ответа сервера.

**Критерий правильного результата:** Служба работает, подключение успешно, три параметра совпадают с вариантом.

## Что сдаётся в LMS

Один файл `C3_S6_LR01_Фамилия_Группа.docx` в формате DOCX. Вставьте в него:

- Состояние службы с её фактическим именем.
- Результат SELECT VERSION(), @@port, @@datadir.
- Фрагмент конфигурации без секретов.
- Таблица «ожидалось / получено» по параметрам варианта.

## Самопроверка

- Получен и сохранён результат «Журнал установки и карта конфигурации экземпляра».
- Использован индивидуальный вариант, а значения варианта указаны в отчёте.
- Результат проверен отдельным действием, а не только визуальной оценкой.
- Команды, SQL-код и фрагменты журнала читаемы; секреты и пароли скрыты.
- Вывод отвечает на ситуацию и объясняет принятое решение.
