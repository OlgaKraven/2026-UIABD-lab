# Запуск учебного стенда

Базовая среда курса — отдельная учебная виртуальная машина с MySQL Community Server 8.4. Первые работы посвящены установке и службе Windows: контейнер не заменяет эти результаты. Word и CSV доступны без сети после распаковки; установка СУБД, Grafana и Prometheus требует заранее подготовленных дистрибутивов либо доступа к сети.

1. Сверьте номер варианта, имя службы, порт и имя базы. Войдите клиентом в свой экземпляр. Пароль вводите интерактивно, не сохраняйте в отчёте.
2. Для SQL-работ создайте новую пустую базу с именем своего варианта. Проверьте SELECT DATABASE(), @@port, VERSION(). Не выполняйте учебные скрипты в общей базе.
3. В новой базе последовательно откройте и выполните sql/service_ops_schema.sql и sql/service_ops_seed.sql. Если таблицы уже созданы в предыдущей работе, повторно эти файлы не запускайте.
4. Ожидаемое начальное состояние: 10 таблиц, 30 заказов, 33 позиции заказов, 3 филиала. Проверьте COUNT(*) в orders, order_items и branches. В работах по схеме и импорту исходное состояние задаёт задание: не загружайте seed до выполнения самостоятельного создания структуры.
5. Перед запросами семестра 7 выполните parameters.sql своего варианта в той же сессии. Команды с незаполненными выражениями являются каркасом задания; допишите их перед запуском. Файлы procedure_case.sql и trigger_case.sql применяются после создания соответствующей процедуры или триггера.
6. Для исследования нагрузки задайте SET @volume_rows = число_из_варианта; и выполните sql/generate_volume.sql. Он добавляет отдельные заказы с ID от 100001; повтор с тем же значением не создаёт дубликаты. Запишите фактические объём, план и измерения, не используйте чужие времена как свои.
7. SQL/JSON/YAML можно открывать обычным текстовым редактором. CSV из папки «Данные» импортируйте как UTF-8 с разделителем «точка с запятой». Числовые значения с точкой при необходимости импортируйте с соответствующей локалью. SQL-скрипты не читают CSV автоматически.

## Возврат к исходному состоянию

Перед изменением сохраните собственный SQL и отчёт. Для проверки отката используйте START TRANSACTION и ROLLBACK только для операций, поддерживающих транзакцию; DDL может завершить транзакцию неявно. Процедура с собственным COMMIT не отменяется внешним ROLLBACK. Для неё создайте отдельную учебную копию и сверяйте остатки до и после каждого вызова.

Если состояние повреждено, создайте новую базу с согласованным суффиксом, загрузите схему и seed, затем перенесите только проверенные собственные объекты. Не удаляйте прежнюю базу автоматически. Для восстановления из backup/service_ops_backup.sql используется отдельная база service_ops_recovery; если она уже существует, согласуйте новое имя и одинаково измените его в копиях скриптов резервной копии и проверки.

## Мониторинг

Сначала подтвердите подключение exporter к своему MySQL, затем подставьте адрес exporter в prometheus.yml. Метки environment и instance_variant должны отличать учебную среду и вариант. В Grafana выберите тот же источник Prometheus и часовой пояс UTC. Не заменяйте отсутствующие измерения нулём. Готовые CSV описывают учебный сценарий; они не подтверждают запуск вашей системы сбора.
