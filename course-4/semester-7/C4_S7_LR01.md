## Ситуация

Руководителю нужен список открытых заказов филиала на контрольную дату. Предыдущий отчёт пропускал записи на границе суток.

## Цель и навык

**Цель:** Получить на серверной базе точную выборку по операционному условию и доказать её полноту.

**Практический навык:** Формулировать фильтры с датами, статусами и NULL, проверять граничные записи.

## Исходные данные

- Развёрнутая service_ops с учебными данными.
- Филиал, контрольная дата и набор статусов из варианта.
- Описание часового пояса и полей заказа.
- Контрольные идентификаторы двух граничных записей.

## Ограничения

- Не изменяйте данные.
- Не используйте SELECT *.
- Поясните включение или исключение граничных значений.

## Логический маршрут

1. Запишите условие выборки словами.
2. Выберите только необходимые столбцы.
3. Примените фильтры филиала, статуса и диапазона дат.
4. Упорядочьте результат воспроизводимым образом.
5. Проверьте две граничные записи отдельными запросами.
6. Сравните количество строк основной выборки с независимым COUNT(*).

## Что нужно помнить

- BETWEEN включает обе границы.
- Для полуинтервала дат используют >= начала и < следующего дня.
- NULL проверяют IS NULL, а не = NULL.
- ORDER BY делает представление результата воспроизводимым.
- COUNT(*) служит независимой проверкой объёма.
- Успех — границы объяснены, количество и записи согласованы.

**Пример формы результата:** Основная таблица и контрольный COUNT(*) показывают одинаковое число строк; две граничные записи разобраны отдельно.

**Типичная ошибка:** Фильтр дат построен через строковое совпадение или BETWEEN без анализа верхней границы.

**Критерий правильного результата:** Выборка соответствует варианту и совпадает с независимой проверкой количества.
