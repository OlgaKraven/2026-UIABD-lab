# C4_S8_LR05. Сравнение MySQL и PostgreSQL по заданной учебной ситуации

**Курс:** 4  
**Семестр:** 8  
**Блок:** Наблюдение за работой сервера и выявление технических проблем  
**Связанная лекция:** [Сравнение MySQL и PostgreSQL](https://olgakraven.github.io/2026-UIABD4-lecture/?topic=s08-05-database-platform-comparison&slide=1)

**Индивидуальный вариант:** 01–30; используйте строку своего номера из матрицы семестра.

## Ситуация

Организация переносит учебный сервис на вторую площадку и выбирает платформу. Решение нужно обосновать практическим мини-развёртыванием, а не перечнем брендов.

## Цель и навык

**Цель:** Выполнить одинаковый минимальный сценарий на MySQL и PostgreSQL и выбрать платформу по наблюдаемым различиям.

**Практический навык:** Сравнивать установку, роли, типы, отдельные конструкции SQL и средства наблюдения без ложной универсализации.

## Исходные данные

- Одинаковая учебная ситуация и минимальная схема для двух платформ.
- MySQL 8.4 и PostgreSQL 18 в изолированных экземплярах.
- Матрица критериев: установка, роли, типы, запрос, мониторинг.
- Вариант приоритета организации.

## Ограничения

- Не объявляйте особенность одной платформы свойством всех СУБД.
- Не сравнивайте разные наборы данных.
- Решение относится только к заданной учебной ситуации.

## Логический маршрут

1. Разверните минимальную схему и одинаковые строки на обеих платформах.
2. Создайте роль чтения и проверьте разрешённую/запрещённую операцию.
3. Выполните один запрос с группировкой и сравните результат.
4. Сопоставьте выбранные типы и синтаксические различия.
5. Найдите штатный источник состояния подключений/активности на каждой платформе.
6. Заполните матрицу фактов и выберите платформу по приоритету варианта.

## Что нужно помнить

- MySQL и PostgreSQL имеют разные модели учётных записей/ролей.
- Одинаковое имя типа не гарантирует полностью одинаковое поведение.
- Результат запроса должен совпасть по смыслу и данным.
- Средства наблюдения сравнивают по задаче, а не числу экранов.
- Вывод ограничен учебной ситуацией.
- Успех — каждый критерий подтверждён действием на обеих платформах.

**Пример формы результата:** Матрица имеет строки «развёртывание, роль, тип, запрос, наблюдение» и два столбца фактов; третий столбец объясняет влияние на выбор.

**Типичная ошибка:** Сравнение превращается в реферат или переносит синтаксис одной СУБД на другую без проверки.

**Критерий правильного результата:** Пять критериев подтверждены на обеих платформах, выбор следует из приоритета варианта.
