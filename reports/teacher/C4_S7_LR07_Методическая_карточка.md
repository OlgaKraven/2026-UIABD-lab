# C4_S7_LR07. Разработка триггера для учётной операции

> Материал преподавателя. Не включать в студенческий шаблон и публичную страницу стенда.

## Цель и формируемый навык

**Цель:** Создать прозрачный триггер аудита изменения статуса заказа и доказать его срабатывание.

**Навык:** Использовать OLD/NEW, ограничивать условие срабатывания и проверять побочные записи.

**Компетенции:** ОК 01, ПК 7.1, ПК 7.2, ПК 7.3.

**Связь с лекцией:** [Хранимые процедуры и триггеры](https://olgakraven.github.io/2026-UIABD4-lecture/?topic=s07-03-procedures-and-triggers&slide=1).

## Индивидуализация

Назначьте студенту один вариант от **01 до 30** по ведомости группы. Номер сохраняется для всех работ семестра; параметры берутся из соответствующей строки файла `inputs/variants/c4-s7-variants.csv`. Для работ с инцидентом к номеру привязана одноимённая карточка случая.

## Исходные данные

- Таблицы orders и order_status_audit.
- Перечень отслеживаемых переходов.
- Пользователь и заказы по варианту.
- Набор UPDATE для проверки.

## Ожидаемый и эталонный результат

**Ожидаемый результат:** Триггер аудита и матрица проверок срабатывания.

**Эталонная проверка:** Количество записей аудита совпадает с числом реальных переходов статуса.

**Ключ к ситуации:** Шум появляется без условия OLD/NEW; рекурсия — при попытке менять исходную таблицу из её триггера.

## Правильная последовательность действий

1. Определите событие, момент и таблицу триггера.
2. Сформулируйте минимальный состав записи аудита.
3. Создайте AFTER UPDATE-триггер с сравнением OLD и NEW.
4. Выполните UPDATE без изменения статуса и проверьте отсутствие записи.
5. Выполните допустимое изменение статуса и найдите запись аудита.
6. Проверьте пользователя, время, старое и новое значение; объясните границы решения.

## Допустимые варианты

- AFTER UPDATE-триггер аудита.
- Прикладной аудит — допустимая альтернатива, если серверный триггер не оправдан.

## Типичные ошибки и сообщения

**Методическая ошибка:** Триггер срабатывает на любой UPDATE и создаёт шумовые записи.

- `TRIGGER already exists`
- `Can't update table ... because it is already used`
- `Column count doesn't match`

## Подсказки преподавателя

1. Попросите студента сначала назвать проверяемую гипотезу и только затем показывать действие.
2. При широком или разрушительном действии верните к ограничению учебной среды и минимальному изменению.
3. Требуйте независимую проверку результата, а не только отсутствие сообщения об ошибке.
